# Импорт бланков VetAF

Импорт добавочный: новые документы, версия 1, отдельные лабораторные исследования.
Существующие документы, версии, результаты, счета и услуги не обновляются.
Нелабораторные шаблоны находятся в категориях `VetAF · архив · …`; импорт не
подключает их к лечению, помощнику или рассылкам. Старые юридические тексты
не предназначены для выдачи без проверки реквизитов.

Оригинальный HTML и SHA-256 сохраняются в метаданных импортированного документа.
Полный исходный экспорт и подготовленный пакет — в закрытой резервной копии,
не в Git. Числа, обозначения и единицы переносятся без медицинского исправления.
Нормы требуют проверки ответственным врачом по виду животного и анализатору.
Отсутствующие нормы остаются пустыми.

## Рабочий процесс

В приёме или стационаре выбирают настроенное исследование, затем заполняют
показатели. Новая карточка фиксирует версию бланка и нормы выбранного вида.
Переключение/редактирование шаблона не меняет ранее созданные карточки.
Печать новых карточек отражает сохранённые результат, единицы и нормы.
В стационаре карточка результатов сама не создаёт второй счёт: стоимость
услуги учитывается существующими назначениями. В приёме исследование создаёт
одну позицию услуги, повторное сохранение результатов её не дублирует.
Доступ владельца остаётся по действующим правилам: результаты завершённых
показателей, без черновых значений и внутренних комментариев.

## Перенос

1. `python3 scripts/prepare-vetaf-templates.py source.json NEW_OUTPUT_DIRECTORY`
2. Подготовить закрытый mapping.json: `actorId`, `importedAt`, `links`, где
   ключ — sourceId, значение — `{serviceId, expectedTitle}` либо `null`.
   Связи по сходству названий автоматически не угадываются.
3. Собрать API; проверить пакет и резервную копию целевой базы.
4. `node scripts/import-vetaf-templates.cjs prepared.json source.json mapping.json`
   — только проверка/план.
5. Повторить с `--apply` после проверки целевой установки. В контейнере задать
   `CRM_APP_ROOT=/app`. Импорт выполняется одной транзакцией, с аудитом.
6. Повторный dry-run должен показывать ноль новых документов и исследований.

Неопределённая связь сохраняется как неактивное исследование с бланком;
настроить услугу можно штатным редактором лаборатории. Изменённые врачом
импортированные записи повторный запуск не перезаписывает. Изменение исходного
пакета с тем же source URL требует отдельной процедуры обновления версий.
