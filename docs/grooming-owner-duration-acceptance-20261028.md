# Уточнение длительности — уведомление клиента

По прямому уточнению владельца клиент видит актуальную длительность существующей записи и ориентировочное окончание. При изменении приходит GROOMING_CHANGE через MAX: было / стало, начало и новое ориентировочное окончание. Первичный выбор свободного времени на сайте сохраняет только начало и общую оценку 1,5 часа.

Уведомление создаётся в одной транзакции с изменением записи. Повторный clientKey и изменение на ту же длительность не дублируют сообщения. Согласие клиента, тихие часы и защита от повторной внешней доставки сохраняются.

Кабинет обновляет только время в карточках при возвращении на страницу и не чаще одного раза в минуту, пока видима страница с активной записью. Запись/перенос/выбранный слот и незавершённая операция блокируют фоновый запрос. Полная перезагрузка страницы и сброс введённых пожеланий не нужны.

Проверено локально: календарь (11 сценариев), два сценария публичных мест/занятости, реальный HTTP API → gateway → локальный HTTP MAX, однократность при потере подтверждения, отказ от уведомлений, неизменность начала/цены/места и прав. Пять проверок UI покрывают текущую длительность, полночь, обновление карточек/версии без замены формы, скрытую страницу и редактирование, гонку запроса и отказ транспорта.

Поправка выложена и подтверждена: `crm-grooming-owner-duration-20261028-r1`, источник `4db748e0236b4b294bca8171550f3cefed49a8db`; receipt в `docs/releases/2026-10-28-grooming-owner-duration/deployment-receipt.json`. Тестовый HTTP MAX не является подтверждением доставки на физический телефон.
