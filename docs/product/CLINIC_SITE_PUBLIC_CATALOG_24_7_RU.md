# Публичный прайс TemichevVET: интеграция CRM и сайта

Дата: 05.09.2026. Статус: локальный код и синтетическая проверка готовы. Production deployment и миграции не выполнялись.

## Как работает

`Карточка услуги в CRM → разрешённый снимок → защищённый gateway → публичный GET → страница /prices`.

1. Сотрудник с существующим правом редактирования каталога отмечает «Показывать в прейскуранте на сайте». Флаг по умолчанию выключен, в том числе у всех существующих услуг после миграции.
2. Фоновая задача CRM раз в 30 секунд выбирает `isActive=true, publicOnWebsite=true`. Не вмешивается в сохранение услуги; сбой шлюза не блокирует работу сотрудника.
3. Передаются только id, название, название категории, тип цены и сумма/границы. Описание, расходники, себестоимость, НДС отдельным полем, счета, сотрудники, владельцы и пациенты не передаются. Публичную категорию также нужно проверить перед отметкой услуги.
4. `PUT /internal/v1/clinic/catalog` защищён существующим `X-Owner-Gateway-Secret`. Секрет остаётся только в серверных переменных окружения. Клинический API не открывается посетителям.
5. Gateway сохраняет один полный снимок в отдельной `PublicClinicCatalog`, атомарное обновление допускается только при более новом `capturedAt`. Старые/повторные доставки не откатывают цены. Пустой новый снимок снимает с публикации весь ранее опубликованный прайс.
6. `GET /v1/public/clinic/catalog` не требует авторизации, не возвращает клиническую информацию, отдаёт `Cache-Control: no-store`. Клиент перечитывает раз в 60 секунд. При здоровом соединении обычная задержка изменения — до примерно 90 секунд плюс сетевое время. При сбое точный срок не обещается.
7. Снимок старше 24 часов считается устаревшим, суммы скрываются. Клиент дополнительно проверяет дату, валюту и структуру. Вместо заведомо старых чисел — телефон клиники. Это защитная граница, не гарантия неизменности цены до истечения суток.

## Цены

- `FIXED`: фиксированная сумма, включая допустимый ноль.
- `FLOATING` с корректными обеими границами: публичный `RANGE`, «от–до».
- Неизвестный тип, отсутствующие/некорректные границы: `ON_REQUEST`, без подстановки нижней границы как точной цены.
- Прейскурант не является автоматическим расчётом всего лечения. Сайт поясняет, что состав процедур, препараты и стационар уточняются отдельно.
- До 5000 позиций. Превышение не обрезает прайс молча: снимок не отправляется, фиксируется безопасное предупреждение без тела данных.

## Включение после отдельного подтверждения цели deployment

Не путать сайт клиники, публичный PWA и служебную CRM. Сначала подтвердить актуальные хосты и роль gateway. Не менять DNS и не перезапускать соседние сервисы автоматически.

1. Сохранить резервные копии двух БД и текущих application image/revision; проверить откат. Старые volumes не удалять.
2. На выбранных CRM и gateway применить соответствующие additive migrations до запуска кода, который читает новые поля/таблицу. Команды и env для реального хоста проверить в его release-процедуре. Миграция не публикует услуги автоматически.
3. Развернуть совместимый API CRM, gateway и web CRM. Сначала оставить `CLINIC_SITE_CATALOG_SYNC_ENABLED=false`.
4. Проверить название/роль получателя в `OWNER_GATEWAY_URL`; сохранить существующий `OWNER_GATEWAY_SYNC_SECRET`, не копировать его на сайт и не писать в `VITE_*`.
5. Выбрать согласованные услуги флажками CRM. После этого включить `CLINIC_SITE_CATALOG_SYNC_ENABLED=true` в CRM API и проверить безопасное предупреждение/снимок. Нужен один канонический источник каталога и синхронизированные часы серверов.
6. На домене сайта проксировать только публичный `GET /v1/public/clinic/catalog` в gateway; внутренний PUT не открывать через домен сайта. Для другого origin задать allowlist `OWNER_GATEWAY_PUBLIC_SITE_ORIGINS` на шлюзе. Предпочтителен same-origin reverse proxy, тогда `VITE_PUBLIC_GATEWAY_URL` пустой.
7. К существующему CSP сайта добавить `frame-src https://yandex.ru` для официального виджета, не ослабляя политики gateway. Не добавлять inline-скрипты третьих сторон и не включать аналитику без согласия.
8. Для реальной формы использовать существующий `POST /v1/public/clinic/inquiries`, HTTPS, доверенный proxy/IP для rate limit, согласованный документ обработки данных. В сборке: `VITE_INQUIRIES_ENABLED=true` и `VITE_SITE_PRIVACY_URL=https://...` с реальным согласованным адресом, не заглушкой.
9. Отдавать готовые файлы `dist/client`, реальные 404 для неизвестных путей; исключить `/photo-plan`. Включать `SITE_INDEXABLE=true` только для согласованного боевого сайта. Шаблон Sites worker содержит SPA fallback и сам по себе не решает production 404.
10. Принять на настоящем устройстве: изменение согласованной услуги в CRM → обновление GET → изменение страницы без reload; снятие отметки/архив; отсутствие утечки внутренних полей; реальное получение одной тестовой заявки администратором без создания дубля. На production изменения/тестовые записи делать только с согласованными точными целями и способом восстановления.

## Откат

Отключить задачу CRM (`CLINIC_SITE_CATALOG_SYNC_ENABLED=false`) останавливает новые отправки, но не удаляет уже опубликованный снимок: он остаётся доступен до 24 часов. Для немедленного снятия прайса закрыть публичный GET на reverse proxy либо отправить новый пустой снимок из согласованного канонического источника. Старую доставку после пустого снимка шлюз отвергнет. Вернуть прежние application images; additive поле и таблицу можно оставить для безопасного отката без удаления данных. Не выполнять DROP и не удалять volumes в качестве отката сайта.

## Яндекс отзывы

Источник существующего сайта: организация `1809394242`, карточка «Айболит», Каспарова 27/2. В новой странице используется официальный `https://yandex.ru/maps-reviews-widget/1809394242?comments`, а не парсинг/собственная БД отзывов. При проверке в браузере 05.09.2026 виджет показал 4,8 / 354 отзыва / 805 оценок; эти числа не зафиксированы в UI и не заявляются неизменными.

Официальная справка: https://www.yandex.ru/support/business-priority/ru/reviews/reviews . Первое подключение только по кнопке посетителя; при недоступности Яндекса остаётся ссылка на отзывы. Синхронизация отзывов не относится к CRM.

## Доказательства и ограничения

287/287 тестов CRM, 7/7 тестов сайта; API/gateway build и web typecheck успешны. В браузере на отдельном localhost-стенде проверены: 1000 → 1500 ₽ без reload; диапазон; поиск/сброс; архивирование; скрытие данных старше суток. Данные полностью синтетические, repository-сервисы экспорта и gateway действительно используются, PostgreSQL в стенде заменён хранилищем в памяти. Миграции на реальном PostgreSQL, TLS/CORS/reverse proxy и рабочие цены ещё не проверены.
