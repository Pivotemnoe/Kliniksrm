# Скорость ручного ввода и исправления накладных — 9 октября 2026

При изменении одного поля форма подписывалась на весь массив позиций и повторно строила все карточки с Ant Design Select/InputNumber. Поиск был общим для всех строк. По мере добавления позиций работа браузера росла, хотя ввод количества не отправлял сетевых запросов.

Каждая строка теперь отдельно подписывается на конкретные поля с точным совпадением пути. Это также исключает обновление строки 10 при вводе в строке 100. Общая сумма подписана отдельно; автоподстановка суммы принадлежит самой строке и сохраняется при удалении предыдущей позиции. Поиск включается только в открытом поле, ждёт паузу 250 мс, возвращает до 50 товаров и отменяет устаревшие запросы. Закрытые поля не подписываются на обновления запроса других строк.

## Проверки

- Настоящая форма из исходного кода, синтетические товары и заглушки HTTP: создание и исправление на 10/50/100 строках. До исправления ввод количества обновлял все строки; после — одну. Ввод количества не вызывает HTTP.
- На 100 строках до исправления работа React составляла примерно 450 мс на изменение; после — примерно 11 мс. Это измерение в локальном браузере с React Profiler, не гарантия времени на компьютерах клиники.
- Браузер: исправление и отправка всех 100 ID; суммы с запятой и копейками; скидка; поиск препарата вне первых 50 результатов; обновление только позиции 100; автоматический расчёт количества и упаковки; сохранение ручной суммы; добавление/удаление и смена индексов; запрет удаления проведённых позиций; проверка обязательных полей.
- 27 относящихся к складу и накладным проверок: PASS. В отдельной локальной PostgreSQL — 5 существующих интеграционных проверок и новая проверка накладной на 100 строк: PASS. Создание 589 мс, исправление 244 мс; неизменные строки не создают новые движения, повторное сохранение не дублирует остатки.
- TypeScript и production web build: PASS. API и схема базы не изменяются.

Артефакты локальной диагностики: `outputs/stock-invoice-performance-20261009/` (`before.txt`, `after.txt`, `functional.txt`, `web-build.log`). Тестовый стенд не обращается к рабочим данным. Начальная отрисовка очень длинной формы всё ещё зависит от количества контролов; это исправление устраняет повторную отрисовку всех позиций при вводе.
