# Вакцинации и лист осмотра — 24 сентября 2026

## Что изменилось

- Просрочка определяется по последней сделанной вакцинации пациента, а не по максимальной дате следующей вакцинации. Учитываются варианты регистра, пробелов и фасовки «1 доза»; «Мультифел» сопоставляется с «Мультифел 4». Произвольное нечёткое объединение разных вакцин не используется.
- Закрытая связанная задача (выполнена, отменена, архивирована) убирает напоминание. Более старые дозы при этом не возвращаются в предупреждения.
- Создание/исправление вакцинации закрывает открытые задачи предыдущих доз того же препарата и отменяет ещё не отправленные сообщения по ним. История прививок, деньги и склад этим действием не меняются.
- В раскрытом списке вакцинаций доступно «Убрать напоминание». Укажите причину или выберите «Отказались» / «Не придут». Действие применяется к перечисленным вакцинам этого животного. Следующая новая вакцинация сможет создать новое напоминание. Уже отправленные сообщения не отзываются.
- Добавлено состояние «Без изменений».
- У манипуляций доступно «Открыть документ»: поиск существующего шаблона, выбор текстовых блоков/строк составного документа, редактирование перед добавлением. Текст дополняет поле и сохраняется его обычным автосохранением. Ограничение 4000 символов проверяется без обрезки.
- Убрана отдельная причина обращения из листа осмотра и проверки помощника. Старые сведения сохраняются и показываются вместе с анамнезом в истории/печати; прежний локальный черновик переносит этот текст в анамнез. Совместимость API со старыми клиентами сохранена.
- Инструкция внутри CRM обновлена. Обязательный диагноз и текст для завершения первичного приёма, автосохранение и привычная навигация сохранены.

## Проверки перед выпуском

417 автоматических тестов: успешно. Включены оба случая с фотографий (ранняя и поздняя ревакцинация), закрытые задачи, другие животные/вакцины, отсутствие следующей даты, отклонение чужих идентификаторов до записи, отмена очереди сообщений и извлечение строк документов. TypeScript API/web и сборка web: успешно.

На локальном интерфейсе с вымышленными данными проверены выбор строк документа, вставка и сохранение после перезагрузки; состояние «Без изменений»; снятие просрочки без изменения напоминания другого животного. Это не проверка на медицинских записях клиники.

## Отдельная сетевая проблема

На фотографии ERR_ADDRESS_UNREACHABLE при открытии 192.168.199.10:3000 — сбой доступа рабочего компьютера к адресу сервера до загрузки приложения. Проверка TECNO: адрес 192.168.199.10/24, шлюз 192.168.199.1, локальная сеть и localhost отвечают HTTP 200. Полный путь с пострадавшего ноутбука при пропадании WAN пока не воспроизведён. Эти изменения не объявляются исправлением сети. Wi-Fi, маршруты и защита компьютеров не менялись.

## Выпуск

Без миграций базы. Только API и web на TECNO; свежая резервная копия БД/настроек, точные образы по commit SHA, проверка здоровья и неизменности PostgreSQL/Redis/MinIO/backup. При неуспешной проверке вернуть предыдущие настройки и образы API/web.

## Идея на следующий этап (не реализована)

Типы «Операция» и «Послеоперационный» могут открывать специализированную вкладку внутри существующей сущности приёма, аналогично вакцинации: хирургический протокол/анестезия/послеоперационные назначения. Общими остаются пациент, диагнозы, счёт, документы и связь со стационаром. Сначала согласовать поля с врачами.
