# Клинический модуль Авито

Модуль работает отдельно от груминга CRM. Объявление определяет направление CLINIC/GROOMING/HOTEL. Первое подключение включает только CLINIC, ручной режим, шесть клинических карточек и утверждённую владельцем таблицу восьми вариантов диспансеризации. Направления GROOMING/HOTEL и озоновая ванна выключены. Записи на приём автоматически не создаются.

Семь подготовленных объявлений импортируются только как новые DRAFT без согласования публикации. Фотографии и содержимое берутся из приватного пакета `reviewed`, а актуальные услуги и филиалы проверяются сервером. Личные диалоги и состояние локального пилота не переносятся.

Для будущего направления груминга предусмотрен отдельный промпт: посетитель переходит на сайт груминга, если правила Авито разрешают такую ссылку; контакты и время оформляет на сайте. Эта доработка и проверка допустимости ссылки в текущий запуск не входят.

## Подготовка

Используйте отдельную чистую рабочую ветку с текущим грумингом, ускорением накладных и исправлениями сайта клиники. Старый пакет `avito-clinic-20261019-r1` не соответствует текущей боевой сборке.

Соберите API/gateway, выполните проверки Авито, прав, независимости модулей и груминга на отдельных синтетических базах. Две новые миграции добавляют только таблицы Авито и права director/administrator. Уже применённые миграции и таблица ClinicModuleInstallation сохраняются.

Перед запуском `prepare-context.mjs` задайте `AVITO_SCHEMA_ENGINE_FILE`: проверенный schema-engine Prisma 6.19.3 для Linux musl/OpenSSL 3 с SHA-256, указанным в скрипте. Клиент генерируется внутри образа без сетевого доступа, с библиотекой существующей сборки.

Укажите свежие image ID/reference API/Web/gateway и реального директора в приватном release.json. Сравните контрольные суммы всех применённых миграций. Проверьте все существовавшие поля и модели Prisma. Контекст не содержит ключей, клиентской переписки, дампов или клинических записей.

Dockerfile.api/gateway расширяют фактически работающие образы. В API разрешены только новый каталог Avito, два файла общего реестра модулей, app.module, meta и Prisma. В gateway разрешены четыре новых файла Avito, app.module, расширение существующего клиента ИИ и Prisma. Остальные файлы, включая груминг, сайт, кабинет владельца и накладные, должны совпасть по SHA-256.

## Выпуск и откат

На TECNO используется `backup-database.ps1`, затем `release-clinic.ps1`. Копия базы восстанавливается в изолированном PostgreSQL без сети; новая миграция проверяется на восстановленной копии. `Apply` требует свежую проверенную копию, точные образы и отключённый seed. Меняется только API; Web, PostgreSQL, Redis, MinIO и backup не пересоздаются.

Ключ Авито хранится в приватном файле на сервере с ограниченными ACL и подключается только для чтения через bind mount. Он не включается в образ, Git или журналы. `AVITO_INGEST_ENABLED`, `AVITO_LIVE_SEND_ENABLED`, `AVITO_AI_ENABLED` остаются false. Gateway по умолчанию сохраняет `AVITO_ASSISTANT_MODEL_ENABLED` выключенным; остальные ИИ/MAX/уведомления не перенастраиваются.

Gateway использует `release-gateway.py build`, `backup`, `apply`. Перед его переключением повторно проверьте baseline и согласуйте окно с текущей работой над сайтом. Обновление сохраняет существующие allowlist и секреты. Общий реестр модулей, лицензия и индивидуальные DENY проверяются при инициализации.

После выпуска откройте модуль под действующим директором, проверьте подключение к ожидаемому аккаунту, сохранённые черновики/фото/правила, SPA-переходы и ошибки браузера. Перепроверьте health, клинические счётчики, настройки груминга, доверенные устройства и неизменные контейнеры данных.

Для отката используйте `release-clinic.ps1 -Mode Rollback` и `release-gateway.py rollback` из сохранённого пакета. Скрипты отказываются перетирать последующий выпуск или изменённую конфигурацию. Возвращаются предыдущие образы и настройки приложений; база и новые таблицы не восстанавливаются из старого дампа. Все обращения и изменения после выпуска сохраняются.
