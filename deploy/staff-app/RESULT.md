# PWA сотрудников — первая локальная версия

28 октября 2026. Ветка `codex/staff-mobile-pwa`, исходная линия `c43e0e8c8dd46de80a4616072b1a8f9d2826d1c1`.

Готовы серверная часть, мобильный интерфейс `/staff/`, настройка возможностей сотрудников в CRM и пакет для последующего согласованного развёртывания. В рабочую CRM версия не установлена.

## Согласованное распределение

- Клиника: все приёмы клиники по умолчанию на экранах «Сегодня» и «Записи» по существующим правам; «Мои приёмы» остаётся дополнительным фильтром. В общем списке указан врач. Смены, свои задачи, входящие сообщения и карточка записи. Запись на приём с телефона включается сотруднику отдельно.
- Грумер: свой календарь, поиск клиента по полному телефону, добавление клиента и питомца, создание и перенос своих записей, отметки прихода и выполнения, отмена и неявка. Создание и перенос включаются отдельно; чужие записи закрыты.
- Новые и перенесённые записи сохраняются в общей программе, а не в отдельной мобильной базе.
- Уполномоченный сотрудник управляет доступом к приложению, записью и уведомлениями в «Настройки → Приложение сотрудников».
- Настройки приложения не назначают роль администратора. Рабочие роли врача, кассира и склада сохраняются; финансовых разделов в PWA нет.

## Проверено

- API, PWA сотрудников и основной веб-интерфейс: успешная сборка с проверкой TypeScript.
- **33 из 33 автоматических проверок** на чистых изолированных схемах с вымышленными данными. Включают права и запреты, доверенное удалённое устройство, отдельное разрешение мобильной записи, запрет остальных удалённых изменений, конкурирующие записи, повтор команды, перенос с версией, принадлежность клиента и питомца, ограничения уведомлений и кеша.
- В браузере 390×844: грумер создал запись в 10:45, перенёс её на 13:00, повторно открыл после перезагрузки и отметил приход. Уведомление отмечено прочитанным; уменьшившийся счётчик сохранился после перезагрузки.
- Врач без дополнительного разрешения получил просмотр без кнопки записи. После включения отдельного разрешения клиническая запись на 15:00 создана через форму и появилась в общем календаре.
- Уточнение от 28 октября: врач без роли администратора сразу видит приёмы всех врачей за выбранный день. В мобильном примере открыта карточка приёма коллеги; фильтр «Мои приёмы» оставил только личную запись и сохранился после обновления. На «Сегодня» также выбран общий список. Серверная проверка подтверждает общий список по умолчанию и личный список только по явному фильтру.
- Переключатель сотрудника сохранён через интерфейс и повторно прочитан с сервера после загрузки страницы.
- При 320 пикселях ширина страницы равна ширине экрана; при отключении сети кнопка записи фактически заблокирована.
- Итоговая собранная версия повторно открыта в браузере: используются ресурсы `/staff/assets/`, область service worker — только `/staff/`, в кеше — только публичный `/staff/offline.html`. API и персональные карточки не кешируются.

Ручные сценарии проверялись до очищения тестового профиля для итогового автоматического прогона. Затем локальный показ создан заново. Исправлены найденные при ручной проверке лишнее поле в запросе переноса и неверная метка «Новое» у заменённых уведомлений.

## Приёмка и границы

Локальный показ использует вымышленные данные; внешняя доставка выключена. Установка на реальные Android/iPhone, доставка Web Push на телефон, поведение при блокировке экрана и сетях клиники ещё не приняты на устройствах. Клинические уведомления в этой версии доступны внутри приложения; Web Push предусмотрен для груминга.

Для установки PWA на телефоны нужен защищённый адрес HTTPS и доступ к API CRM. Действующие правила доверенных удалённых устройств сохраняются. Текущая сеть, маршрутизаторы, сервер, данные и права реальных сотрудников этой работой не менялись. Госпитальный кандидат не применялся.

Перед рабочим развёртыванием необходимы свежая проверка целевых образов и служб, резервная копия настроек и согласование активации. Предыдущий мониторинг не возобновлялся. Android и iPhone остаются следующим отдельным этапом на общей мобильной основе.
