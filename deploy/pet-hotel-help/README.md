# Инструкции модулей в CRM — отдельное обновление Web

В «Инструкция» добавлены пошаговые разделы груминга, зоогостиницы и Авито. Изменён только HelpPage; API, gateway, данные, правила записи и MAX остаются прежними.

Подготовка: `VITE_API_BASE_URL=/api npm run web:build`, проверка инструкции на локальном стенде, фиксация исходников, свежий preflight, `node deploy/pet-hotel-help/prepare-context.mjs`. Пакет содержит только изменённые web-файлы; Docker сборка поверх текущего Web проверяет SHA256 всех файлов итоговой сборки. Прежние hashed assets сохраняются для открытых вкладок.

На TECNO `run-web.ps1 -Mode Publish` строит кандидат и выполняет `release-web.ps1 -Mode Inspect`, затем `Apply -Execute`. Запускается одноразовым S4U-заданием Task Scheduler под тем же пользователем, без повторяющегося триггера. Результат записывается в `result-Publish.json`; разрыв SSH не завершает задание. После успеха задание удаляется, файлы и журналы сохраняются.

Резервируются текущие env/настройки диагностики и точные изображения. Для Web используется уже проверенная восстановлением база основного выпуска гостиницы, её hash и proof проверяются повторно. Новых записей в БД этот выпуск не делает и при откате данные не восстанавливает. Защищены API, PostgreSQL, Redis, MinIO, backup и том со старыми assets.

Откат только инструкции: `run-web.ps1 -Mode Rollback -PackageRoot <пакет>`. Возвращаются предыдущий Web и сохранённые байты конфигурации. API и данные сохраняются.

На проверенном запуске Task Scheduler используется `-EncodedCommand` с внешним `try/catch`, вызовом `run-web.ps1` с явными `-Root` и `-PackageRoot` и перенаправлением в `launch-output.log`. Это сохраняет проверки принадлежности конфигурации и не затирает более поздний выпуск.
