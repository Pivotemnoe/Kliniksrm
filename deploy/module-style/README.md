# Выпуск оформления CRM и груминга

Оформление принято пользователем 20 октября 2026. Серверная интеграция Авито выпускается отдельно: этот Web содержит её оформление и понятное состояние недоступного серверного модуля. Доступ к разделу по-прежнему требует соответствующих прав; новые права выпуск оформления не выдаёт.

## Сборка

```sh
VITE_API_BASE_URL=/api VITE_AUTH_MODE=protected VITE_GROOMING_QA=false VITE_GROOMING_QA_TRANSPORT=live npm run web:build
```

Основная Vite-сборка включает CRM и `/grooming/`. QA-баннеры, тестовые учётные записи и внешние тестовые транспорты в production-сборку не входят. API, Prisma, миграции, PWA manifest/scope и SW не изменяются. Накладные используют ранее принятую оптимизацию.

На сервере создавать Web-образ поверх точного текущего Web image. Для кабинета владельца создавать образ поверх **текущего** gateway image с заменой только `dist/public/grooming.html` и `grooming.css`. Проверять ID образов, родительские слои, startup command и хэши остальных файлов. Обновления чекапов от 20 октября должны сохраняться.

## Переключение и откат

`release-web.ps1` принимает пакет с `release.json` и свежую резервную копию с квитанцией `verified-backup.json`. Режим `Inspect` ничего не меняет. `Apply` и `Rollback` требуют `-Execute` и явного разрешения пользователя на выпуск. Перед переключением обязательны пробное восстановление базы и проверка файлового архива.

Конфигурация читается в порядке `.env`, затем `.env.runtime`, как в Docker Compose. Повторяющиеся ключи внутри каждого файла запрещены. Итоговый Compose API image должен совпадать с работающим API; его ID дополнительно сверяется с manifest. Это позволяет обновлять Web, сохраняя актуальный API из runtime override.

Откат заменяет только интерфейс и сохранённую конфигурацию выпуска. Текущие клинические записи, сессии, доверенные устройства и подписки не восстанавливаются из старого дампа. При другой версии образа либо изменившейся конфигурации откат отказывается перезаписывать последующий выпуск.

Хэшированные assets старого Web сохраняются в существующем volume: они нужны уже открытым вкладкам сотрудников. Не очищать этот volume вместе с Docker build cache. PostgreSQL, Redis, MinIO, backup-контейнеры и их volumes не удалять. Сохранять текущий и предыдущий образы, принятые QA-копии и квитанции.

Точные пути, ID образов, резервные копии и команды отката конкретного выпуска хранятся в локальном `output/deployments/crm-module-style-20261020-r1/` и на целевых серверах. Клинические данные, `.env` и приватные квитанции не публикуются на GitHub.
