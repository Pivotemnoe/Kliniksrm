# Интегрированная зоогостиница — выпуск 2026-10-20

Авторизованный выпуск CRM и сайта: отдельный модуль зоогостиницы, 8 номеров для кошек и 4 для собак; сайт и общий кабинет владельца используют реальные сохранённые брони CRM. Действующие груминг, Авито, клинические и финансовые данные сохраняются.

## Подготовка

1. Собрать API и owner-gateway, затем Web с `VITE_API_BASE_URL=/api npm run web:build`; выполнить hotel/bridge/delivery/owner и регрессионные проверки. Проверить интерфейс и сохранённую бронь на изолированном стенде 4331/4333. В локальной среде внешний MAX заблокирован.
2. Снять свежие `production-preflight.json`, `database-preflight.json`, `gateway-preflight.json` в `output/deployments/crm-pet-hotel-integrated-20261020-r1/`. Проверить точные исходные изображения и контрольные суммы всех уже применённых миграций. Исходная боевая версия: `908cbbdd0aae9e302fc9b7ed5cc56de00804436d`.
3. Зафиксировать исходники. `node deploy/pet-hotel-integrated/prepare-context.mjs` создаёт пакет с контрольными суммами и BOM для Windows PowerShell 5. При переносе tar использовать `COPYFILE_DISABLE=1`. Linux Prisma engine допускается восстановить из прежнего закреплённого image только при SHA256 `955e3bff1be23248a0922a219f7c4e200acc8fdd1fc72479557c0a9d782bd64a`.
4. Собрать кандидатов поверх текущих production images: `build-clinic.ps1`, `release-gateway.py build`. Сравнение всех остальных runtime-файлов обязательно. Груминг, финансы, склад и Авито не входят в API overlay.
5. Создать новые защищённые backups. `backup-database.ps1` и `release-gateway.py backup` проверяют полное восстановление без внешней сети, новые миграции, запуск кандидата, сохранность прежних записей и идемпотентность инициализации. До успешной проверки переключение запрещено.

## Переключение и контроль

Первым применяется gateway: `python3 release-gateway.py apply`; затем на TECNO `release-clinic.ps1 -Mode Apply`. Пересоздаются только gateway, api и web. PostgreSQL, Redis, MinIO, backup и тома не пересоздаются. `SEED_ON_START=false`. Явно добавляются только переменные PET_HOTEL; MAX credentials/webhook, OWNER_GATEWAY и GROOMING сохраняются.

Инициализация создаёт только модуль и согласованные номера, сохраняет индивидуальные названия/тарифы, включает самостоятельную бронь после проверки конфигурации. Учётные записи, пароли, владельцы, питомцы и брони не создаются. Получателей сотрудников MAX директор задаёт в настройках модуля; чужие получатели автоматически не копируются.

После переключения: health/release revision, 12 номеров, свежий privacy-safe снимок, сайт, общий кабинет и маршрут hotel. Проверить сохранение существующих настроек Grooming/Avito, прежних MAX настроек и ID/времени запуска защищённых контейнеров. Публичный сайт выпускает согласованный чат только после подтверждения готовности backend. Отчёт SENT от провайдера и видимое уведомление на телефоне фиксируются отдельно.

## Откат

На TECNO: `release-clinic.ps1 -Mode Rollback -PackagePath <путь пакета>`. На RU: `python3 <путь пакета>/release-gateway.py rollback`. Сценарии проверяют принадлежность текущих image/config этому выпуску, возвращают сохранённую конфигурацию и предыдущие images. При собственной ошибке переключения откат запускается автоматически.

Новые таблицы и текущие записи сохраняются; старый dump поверх рабочей базы не восстанавливается. Перед откатом согласовать возврат статического hotel-сайта/закрытие брони с его чатом. Не удалять backup, предыдущие images или пакет отката после успешного запуска.
