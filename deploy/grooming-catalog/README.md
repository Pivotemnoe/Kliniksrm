Узкое обновление каталога груминга по прямому сообщению владельца от 21 октября 2026: стрижки собак и кошек без мытья больше не предлагаются. Гигиена, сухое вычёсывание, экспресс-линька и все остальные согласованные цены сохраняются.

Из 218 импортируемых позиций исключены 46 точных catalogKey; 172 позиции остаются. Исходные числовые цены в price-catalog.json сохранены. Старые строки и правила не удаляются: импорт выключает только isActive с увеличением версии. Старые ссылки на брони, суммы и история сохраняются. Новые предложения и публичный каталог дополнительно исключают снятые услуги даже до применения очистки. Услугу нельзя вновь активировать через обычную форму.

Проверки: сборка API; чистый импорт; обновление старого каталога с исторической бронью и активным правилом; идемпотентные повторы; запрет активации; отдельные специалисты, смены, занятость рабочего места, сохранение записи и персональное подключение телефона через HTTP на отдельной временной БД localhost:55449. Внешний транспорт отключён.

Выпуск заменяет только семь файлов grooming в существующем API-образе. Web, Авито, шлюз, статический сайт, базы и другие контейнеры не переключаются. Native release-api.ps1 требует точный исходный образ, хеши конфигурации и пять защищённых контейнеров; готовит свежий pg_dump и проверяет восстановление в изолированной временной БД.

Перед применением retire.cjs сохраняет снимок прайса и правил в закрытой папке резервной копии. Очистка выполняется одной транзакцией под блокировкой расписания, проверяет неизменность снимка и всех остальных данных груминга, сохраняет аудит и идемпотентную квитанцию. verify работает без записей. Авито-настройки и сообщения этот сценарий не меняет.

Откат исполняется packet/release-api.ps1 -Mode Rollback -Execute. Он возвращает предыдущий API и конфигурацию, сохраняя текущую БД. Исключённые владельцем услуги остаются неактивными: обычный откат программного кода не возвращает отменённое предложение. Снимки до/после и полный дамп сохраняются; массовое восстановление БД поверх рабочей CRM не выполняется. При цепочке нескольких откатов перед следующим шагом требуется заново проверить идентичность восстановленного компонента, поскольку пересозданный контейнер получает новый ID.
