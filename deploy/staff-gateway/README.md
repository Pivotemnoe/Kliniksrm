# Удалённый доступ руководителя

Этот комплект предназначен для отдельного российского адреса `staff.temichevvet.ru` на сервере `193.188.23.65`.

## Граница данных

- PostgreSQL, Redis, MinIO, документы и фотографии остаются на TECNO в клинике.
- Российский сервер не получает копию базы и не хранит медицинские данные: он передаёт только текущий HTTPS-трафик.
- TECNO устанавливает исходящий SSH-туннель с оконечным шифрованием до российского сервера. Входящие порты CRM на роутере клиники не открываются.
- Если прямое SSH-соединение TECNO → российский сервер недоступно, узел `5.129.239.104` используется только как слепой TCP-транзит до SSH российского сервера. На нём нет TLS-терминации, ключа внутреннего туннеля, базы, документов или журналов CRM; расшифровать передаваемый трафик он не может.
- Личный кабинет владельца `cabinet.temichevvet.ru` остаётся отдельной системой.

## Безопасный поток

1. Директор локально открывает `Настройки → Удалённый доступ`.
2. Первое включение и создание одноразовой ссылки выполняются только внутри клиники.
3. Ссылка действует 5–30 минут и привязывает одно устройство к конкретному директору или управляющему.
4. После привязки руководитель входит под личным логином и паролем.
5. Nginx удаляет любые клиентские служебные заголовки и добавляет собственную секретную отметку шлюза.
6. CRM проверяет отметку, включённую политику и доверенное устройство. Отзыв устройства немедленно завершает связанные сеансы.
7. Nginx не записывает access-log этого адреса, чтобы одноразовый токен приглашения из URL не попал в журналы.

## Что требуется перед публикацией

- DNS `staff.temichevvet.ru` на `193.188.23.65`;
- отдельный случайный `REMOTE_ACCESS_GATEWAY_SECRET` не короче 32 байт в конфигурации API TECNO и Nginx;
- отдельный SSH-ключ TECNO → российский сервер с разрешением только `permitlisten="127.0.0.1:23000"`;
- обратный туннель `127.0.0.1:23000` российского сервера → `127.0.0.1:3000` TECNO;
- HTTPS-сертификат и конфигурация из `nginx-staff-https.conf.template`;
- резервная копия перед применением миграции CRM;
- проверка локальной CRM после отключения интернета: она должна продолжить работу без изменений.

Публикация, DNS, Nginx reload, настройка задачи Windows и изменение `.env` TECNO выполняются отдельным согласованным действием. Docker volumes не удаляются.
