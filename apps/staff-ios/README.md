# TemichevVet для сотрудников · iPhone

**Исправление входа 0.1.0 (2):** обычные номер и пароль CRM, роль загружается автоматически; экран приглашения удалён. Подписанный кандидат подготовлен локально. Рабочий API ещё не обновлён, build 2 в TestFlight не загружен. [Точный результат и пакет подключения](Docs/PASSWORD-LOGIN.md).

По прямому разрешению владельца от 28 октября подготовлена отдельная первая TestFlight-версия **TemichevVet Сотрудники 0.1.0 (1)**. Это приложение сотрудников CRM; владельцы клиники используют PWA-кабинет. Фактический статус Apple и граница неразвёрнутого staff/chat API — [TestFlight release](Docs/TESTFLIGHT-RELEASE.md).

Отдельное приложение на Swift/SwiftUI, iOS 17+. Основной интерфейс полностью нативный: `TabView`, `NavigationStack`, списки, формы, карточки, DatePicker и системные подтверждения. WebView и внешние зависимости отсутствуют.

Исходная база: проверенный `813d2ab5a0f5f792d562d3369c51a602b2471e1b`, PWA `codex/staff-mobile-pwa`, исходная линия `c43e0e8…`. Собственная ветка `codex/staff-ios-native`; изменения ограничены `apps/staff-ios/`. Основная рабочая копия CRM и рабочий сервер не изменяются.

## Работа приложения

Врач сразу видит все приёмы клиники, включая коллег; «Мои приёмы» — дополнительный фильтр. Доступны карточки записей, собственные смены, назначенные задачи и входящие сообщения. Кнопка создания клинической записи зависит от серверного `canBook` и индивидуального `staff_app.clinic_booking`. Рабочие роли «Врач», «Кассир» и «Склад» не меняются. Финансовых и зарплатных экранов нет.

Грумер видит своё расписание, смены и уведомления. Создание и перенос зависят от `staff_app.grooming_booking`. Есть поиск по полному телефону, добавление клиента/питомца из каталога, свободное время, создание/перенос, приход, начало/завершение работы, отмена/неявка. Уточнение длительности своей записи использует отдельный штатный endpoint с версией и ключом команды, без выдачи management-прав. Сотруднику показываются полные интервалы. Общий клинический календарь грумеру не запрашивается.

«Сообщения» содержит личные диалоги и заметный вход «Общий чат клиники». Есть активные коллеги, включая грумеров, история, отправка текста до 4000 символов, непрочитанные, пагинация и индивидуальные границы прочтения. Общий канал хранит одну общую запись; автор не получает собственное новое событие. Личные сообщения используют существующий InternalMessage CRM. Источник прежнего канала проверен по ответу пользователя в Android-чате; старые оповещения и личная история сохраняются — [сведения об интеграции](Docs/EXISTING_CHAT_SOURCE.md).

Серверный контракт один для iPhone, Android и CRM. Его снимок и происхождение сохранены в `ServerAdapter/shared-chat`. У сообщений есть idempotency clientKey и чтение до реально отображённого сообщения. Пассивный опрос видимого приложения раз в 8 секунд не продлевает серверную idle-сессию. Фоновый опрос и автоматическая очередь POST отсутствуют.

Права и уведомления включаются по сотруднику в существующей CRM: «Настройки → Приложение сотрудников». Собственная административная роль приложению не требуется. Профиль повторно читается при обновлении и возвращении в приложение; сервер проверяет права каждой команды.

## Сеанс и соединение

Адрес `https://staff.temichevvet.ru` уже настроен. Изменить его можно в отдельной форме подключения. Рабочий адрес требует HTTPS с обычной системной проверкой сертификата. Приложение не добавляет служебные gateway headers и не содержит gateway secret. API сотрудников ещё не развёрнут в рабочей среде: готовность архива не означает доступность новых endpoints.

Приложение вызывает общий `POST /auth/staff-login` с существующими номером/паролем CRM и непрозрачным идентификатором установки. После успешной проверки телефон регистрируется автоматически; приглашение и новая учётная запись не нужны. Роль директора/врача/грумера берётся из CRM. Сервер сохраняет существующие права, политику внешнего доступа, отзыв телефона и сменные ограничения. Старый веб-вход остаётся прежним. [Контракт и границы](ServerAdapter/password-login/README.md).

Пароль используется только для входа/смены и очищается из полей после отправки. Session cookie и device cookie хранятся в Keychain: `WhenUnlockedThisDeviceOnly`, без iCloud; namespace разделён по origin. В UserDefaults — только адрес сервера. Клинические данные находятся только в оперативной памяти. `URLSession.ephemeral`, выключенные URLCache/cookie/credential storage, отказ от HTTP redirects и сторонних origin, без фоновой очереди и повторов команд. При уходе в фон экран прикрыт. После 15 минут бездействия требуется новый вход; собственный таймер не продлевает серверный срок.

Сохранение подтверждается только успешным HTTP-ответом и корректным JSON. После потери ответа результат помечается неизвестным; форма блокирует повтор до проверки расписания. Конфликты версий/времени показываются с ответом CRM. После перезапуска клинические данные загружаются заново. Отображение времени и выбор дня используют МСК независимо от часового пояса iPhone.

Подготовлены настоящая платформенная регистрация APNs, foreground/background response handling и переход по подтверждённому событию в личный/общий чат. Общий серверный APNs transport включён в отдельный снимок API. Реальная инфраструктура и доставка на телефон ещё не настроены/не приняты — [состояние APNs и внешние настройки](Docs/APNS-CONTRACT.md). Внутренние оповещения открытого приложения не называются доставкой push.

## Сборка

Открыть `TemichevVetStaff.xcodeproj`, выбрать `TemichevVetStaff` и iPhone Simulator. Проверенная среда: Xcode 27.1, SDK 27.1, отдельный iPhone 17 Simulator с iOS 27.0. Для TestFlight подтверждён отдельный bundle ID `ru.temichevvet.staff` и подготовлена distribution-подпись. Team и provisioning profile хранятся в приватной локальной конфигурации.

```sh
python3 apps/staff-ios/generate-project.py
xcodebuild -project apps/staff-ios/TemichevVetStaff.xcodeproj -scheme TemichevVetStaff \
  -destination 'platform=iOS Simulator,id=<собственный-UDID>' \
  -derivedDataPath apps/staff-ios/build/DerivedData build
```

Генератор использует только Python stdlib; созданный Xcode-проект сохранён в Git. Подписанная первая сборка загружена в отдельную карточку TestFlight по разрешению владельца. Для функциональной приёмки на iPhone остаются доступный HTTPS staff/chat API, установка тестировщиком и настоящая проверка. Публичная App Store-подача и рабочая установка не выполнялись.

## Изолированная QA

Нужны проверенные локальные синтетические БД из существующего helper на `127.0.0.1:55440`. Подготовка проверяет пользователя/host/имя БД/маркер схемы и search_path. Собственная схема в обеих БД — **`staff_ios_qa_20261028`**. Другие схемы, порты 4251/4252 и рабочие процессы не используются. Docker и сеть не перенастраиваются.

```sh
npm run owner-gateway:build
node apps/staff-ios/QA/build-current-server.mjs
STAFF_IOS_QA_CONFIRM=isolated-synthetic node apps/staff-ios/QA/prepare.mjs
node apps/staff-ios/QA/server.mjs
```

Порты 4268 (API на 127.0.0.1) и 4269 (синтетический gateway на localhost), только loopback. Разные имена host нужны штатной проверке gateway: прямой API не должен называться public host. При занятых портах сервер завершится, чужой процесс не останавливается. Helper использует реальные Nest controllers, auth/permissions guards, Prisma, scheduling, messaging и grooming services. `__qa/*` существует только в helper и управляет вымышленными настройками/сбоями. Пароли и приглашения вымышленные, в приложение не включаются. `QA/runtime.json` не входит в Git.

Снимок общего API компилируется в `QA/.generated/backend`. В основные API/Prisma-файлы изменения не вносятся. Текущий кандидат совмещает мобильные guards PWA, общий chat/native-push API, password login и актуальный груминг `4db748e0`. Отдельная база объединения сервиса груминга — `365ef491…`; клиентские уведомления текущего релиза сохранены. Оригиналы, manifest и точные hashes сохранены в `ServerAdapter/` и `Docs/current-server-candidate.json`. Скрипты capture нужны только для явного обновления снимков; обычная сборка использует сохранённые файлы.

Для HTTP loopback Debug Simulator разрешён только localhost/127.0.0.1. Синтетический proxy снимает Secure у тестовых cookie, потому что реальный AuthController намеренно выдаёт Secure для remote сеанса. Клиент такого преобразования не делает. На реальном iPhone и в Release HTTP запрещён, в Release Info.plist ATS-исключений нет.

Тесты `SecurityContractTests` и `PushRoutingTests` проверяют клиента/Keychain/маршрутизацию; `NativeAcceptanceTests` — нативные действия против helper. `QA/http-acceptance.mjs` проверяет общий серверный контракт. Xcode-тесты запускаются без parallel testing на собственном Simulator. Для чистого повторного набора остановить **только свой** helper и подготовить собственные схемы с `STAFF_IOS_QA_RESET=synthetic-schema-only`; схемы PWA этим режимом не затрагиваются. Переустановка/сброс чужих симуляторов не требуется. В проверке terminal статусов будущая синтетическая запись явно переносится в прошедшее тестовое время; запрет завершать будущий визит не отключается.
