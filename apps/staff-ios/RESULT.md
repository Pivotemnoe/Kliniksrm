## Что работает

- Вход существующей учётной записью CRM, одноразовое приглашение доверенного телефона, Keychain, повторный вход при истечении/отзыве сеанса. Сохранены серверные права и отдельные ограничения удалённого доступа.
- Врач сразу видит приёмы всей клиники; «Мои приёмы» — дополнительный фильтр. Есть карточки, смены, задачи и индивидуально разрешённая запись в клинику.
- Грумер видит своё расписание. Есть поиск клиента по полному телефону, создание клиента/питомца, запись, перенос, приход, начало/завершение работы, отмена/неявка и уточнение длительности собственной записи. Сотруднику показываются полные интервалы.
- Личные диалоги с активными коллегами, включая грумеров, и отдельный «Общий чат клиники»: история, отправка, пагинация, непрочитанные и личные границы прочтения. Используется общий серверный контракт Android/CRM; отдельной локальной истории нет.
- В открытом приложении новые сообщения дают внутреннее оповещение. Настоящие APNs registration/delegate/event routing подготовлены; незапущенная доставка обозначается недоступной.

Роли «Врач», «Кассир», «Склад» сохранены. Финансовых и зарплатных экранов нет. Клинические данные хранятся в памяти; фоновая очередь команд отсутствует. Неопределённый ответ сервера не превращается в успешное сохранение или автоматический повтор.

Проверки выполнялись несколькими прогонами с целевыми повторами исправленных сценариев. Первый общий прогон имел 22 успешных и 3 неуспешных теста: исправлены выбор вложенного native consent switch в тесте и закрытие клавиатуры/системного обучения. Затем найден и исправлен захват устаревшей фазы окна в длительном цикле обновления. Оба таймера контроля бездействия сохранены. Контрольный повтор сообщений, offline/expiry и всех 16 unit/security тестов завершился 19/19; это не выдаётся за один первоначально зелёный полный прогон.

Последний целевой прогон двух чатов завершился **2/2 без ошибок**. Он проверяет именно строку истории после ответа CRM, закрытие клавиатуры через штатное «Готово» и видимость текста без ручной прокрутки. На длинной истории устранено перекрытие области отправки списком: composer размещён через `safeAreaInset`. Подтверждены ответ грумера, оповещение другого врача, перезапуск и общая история с независимым прочтением. Синтетическая история между этими повторами не очищалась.

В Simulator iOS 27 после отправки сообщения и изменения клавиатуры XCTest записал два предупреждения `Invalid frame dimension (negative or non-finite)`. Сценарии завершились успешно; закрытие клавиатуры и переходы проверены. Поведение клавиатуры требует повторной визуальной проверки на настоящем устройстве.

[Скриншоты реального Simulator](Docs/screenshots/) сохранены без изменения пикселей; данные на них вымышленные. Manifest содержит исходный test identifier и SHA-256.

После приёмки собственный loopback helper остановлен. Удалены 708 689 061 байт прежних сборок, кэшей и временных экспортов; исходники, пакеты и четыре доказательных XCTest bundle сохранены. [Запись очистки](Docs/cleanup.json).

## Общий API и история

Снимок общего chat/native-push API получен read-only из Android-копии; файлы и SHA-256 — `ServerAdapter/shared-chat/manifest.json`. В собственном helper он компилируется отдельно, без изменения основных API/Prisma-файлов.

Груминг интегрирован из проверенного коммита `365ef4914b72d487be1e689360bad66f64d08c9a`; сохранены PWA client access tokens, привязка offers к сотруднику, собственные операции и проверки рабочего места/длительности. Оригиналы, явные решения пяти конфликтов и hashes находятся в `ServerAdapter/grooming-duration`.

Ответ о прежнем общем чате найден в чате «TemichevVet сотрудники — нативный Android». Пользователь разрешил отдельную сущность общего чата, если прежний канал не найден. Прежние оповещения/личная история не изменялись; источник старой общей истории пока не идентифицирован. [Подробности](Docs/EXISTING_CHAT_SOURCE.md).
