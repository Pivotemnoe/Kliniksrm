# TemichevVET · сайт 24/7

Опубликовано 05.09.2026: https://clinic.temichevvet.ru/ . Работают 16 страниц, 272 разрешённые услуги из CRM и официальный виджет Яндекса. Незавершённые фотосекции помечены «РАЗДЕЛ В РАЗРАБОТКЕ». Актуальное состояние, доказательства, резервные копии и оставшиеся ограничения — в [отчёте о релизе](../../docs/product/CLINIC_SITE_RELEASE_2026_09_05_RU.md).

Ниже сохранён исторический паспорт локальной сборки **до публикации**. Сведения о работающем localhost и невыполненном deployment в нём больше не описывают текущее состояние.

## Просмотр

- Главная: http://127.0.0.1:4192/
- Прейскурант: http://127.0.0.1:4192/prices
- Отзывы: http://127.0.0.1:4192/reviews
- Фотоплан: http://127.0.0.1:4192/photo-plan — рабочий материал, не раздел публичного сайта.

Сервер запущен агентом. Для повторного запуска: `npm install --prefer-offline`, `npm run build`, `npm run serve:local`. Проверки: `npm test`. Статический сайт находится в `dist/client`; служебные файлы упаковки Sites сохранены без изменения.

## 16 страниц

Главная, о клинике, услуги, приём, УЗИ и рентген, анализы, хирургия, стационар, ветаптека, команда, Константин Темичев, цены, отзывы, контакты, плановый и ночной приём. У каждой страницы отдельные HTML, title, description и canonical. Есть sitemap и настоящая 404 в локальном сервере; поисковая индексация выключена для просмотра. Переходы и контент работают без JavaScript, кроме интерактивного прайса, формы, чек-листа и загрузки виджета.

## Что работает

- Мобильное меню с Escape, постоянные действия: звонок, приём, маршрут.
- Отдельные страницы услуг с подготовкой, стоимостью и раскрывающимися вопросами.
- Поиск услуг, категории, фиксированная цена и диапазон, печать прейскуранта.
- Опрос публичного прайса раз в минуту. При ошибке или данных старше суток суммы скрываются; остаётся звонок и повторная загрузка.
- Форма заявки на отдельной странице: валидация, согласие, скрытое антибот-поле, идемпотентный идентификатор для повторной попытки. В этом просмотре отправка отключена и явно обозначена как макет. Для реального включения предусмотрен существующий `POST /v1/public/clinic/inquiries`; без HTTPS-ссылки на согласованный документ обработки данных отправка не включится.
- Чек-лист перед поездкой: отметки только в памяти страницы, можно распечатать.
- Официальный виджет Яндекс Карт для организации 1809394242. Подключение к Яндексу происходит после нажатия «Загрузить отзывы», рядом всегда доступна прямая ссылка. Рейтинг и тексты не скопированы в исходники. Виджет действительно загрузился при браузерной проверке 05.09.2026.
- Только существующие фотографии. WebP-копии в 640/1280 px; исходные фотографии не изменены. Общий размер всех вариантов изображений около 912 КБ, шрифты локальные.

## CRM: реализовано в коде, не включено на рабочих серверах

См. [инструкцию интеграции](../../docs/product/CLINIC_SITE_PUBLIC_CATALOG_24_7_RU.md). В CRM добавлено поле `Service.publicOnWebsite` и флажок в карточке услуги. По умолчанию все услуги закрыты от публикации. Новая фоновая задача выбирает только действующие отмеченные услуги и передаёт разрешённую проекцию через защищённый gateway. Архивирование или снятие флажка удаляет услугу из следующего полного снимка.

На основном локальном просмотре нет подставленных цен. Проверка изменения 1000 → 1500 ₽ без перезагрузки, диапазона 2000–3000 ₽, архива и устаревания выполнена на отдельном синтетическом стенде 4191. Эти суммы не являются прейскурантом клиники. Хранилище тестового стенда — в памяти; настоящая PostgreSQL-миграция и боевой обмен ещё не проверены.

## Что нужно согласовать до публикации

1. Новые тексты внутренних страниц. Факты взяты из материалов проекта и существующего сайта; перед запуском подтвердить актуальность состава команды, стационара, часов, перечня услуг и реквизитов оператора.
2. Фотографии и карточки остальных врачей. Не подставлялись чужие портреты, вымышленные имена или квалификации. Перечень будущей съёмки выделен отдельно.
3. Разрешённые услуги: сотрудник выбирает их в CRM после установки миграции. Публикуются название, категория и цена — необходимо проверить именно эти названия, включая категории.
4. Точный сервер и роль каждого контура, резервные копии, две миграции, rollout API/gateway/web и reverse proxy. Ни один из этих шагов не выполнен на боевых системах.
5. Документ обработки данных, реальная отправка/получение заявки администратором, согласованная аналитика. Метрика не подключена в новом макете. Чат и окна предложений не переносились в эту версию.
6. Production web-server должен отдавать неизвестные URL как 404 и запрещать `/photo-plan`; шаблон Sites worker оставлен как требует scaffold и имеет SPA fallback. Без соответствующей настройки хостинга это не считать решённым для Sites.
