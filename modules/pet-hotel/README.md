# Самостоятельный модуль зоогостиницы

Локальная версия от 20 октября 2026. Ключ дополнения и лицензии: `PET_HOTEL`.
Маршрут CRM: `/pet-hotel/*`. Управление директором: `/settings/modules`.
В меню отдельный пункт с иконкой ключа между «Груминг» и «Авито», ниже настроек.
Дополнение выключено по умолчанию; миграция не включает его и не создаёт брони.

## Согласованные данные

- 8 кошачьих стеклянных боксов №1–8 и 4 собачьих бокса — прямой ответ владельца.
  Собачьи №1–4 — редактируемые внутренние обозначения.
- Неполные следующие сутки округляются вверх: 2 суток + 3 часа = 3 суток.
- Базовые условия взяты из согласованного сайта зоогостиницы: 700 ₽/сутки,
  150 ₽/выгул, от 48 часов, собаки до 10 кг включительно, заезд 09:00–18:00 МСК.
  Владелец привозит корм и миски. Условия редактирует директор.
- После явной команды «Добавить схему 8 + 4» создаются отсутствующие боксы;
  повторная команда сохраняет исправленные названия и состояния имеющихся.

## Возможности и границы

Календарь месяца, размещения по боксам, поиск и фильтр броней, карточка по ссылке,
создание/перенос, пожелания по уходу, заезд, выезд, отмена и отметка незаезда.
Бокс рассчитан на одного питомца. Свободные места проверяются перед сохранением
и повторно в транзакции. Чужой питомец, неподходящий вид или вес не принимаются.
Просрочивший выезд проживающий питомец продолжает занимать бокс до оформления выезда.

Цена брони хранит снимок ставок и количество оплачиваемых суток/прогулок.
Изменение прайса не переписывает старые брони и их ставки при переносе.
Расчёт в копейках; это стоимость согласованной брони. Платёж, клинический счёт,
автоматический перерасчёт по фактическому выезду или возврат не создаются.

Отдельные таблицы `PetHotelSettings`, `PetHotelRoom`, `PetHotelReservation`,
`PetHotelCommandReceipt`. Общая платформа предоставляет только владельцев,
питомцев, сотрудников, организацию, вход, роли, лицензию и аудит. Медицинский
стационар, приёмы и графики/записи груминга для размещений не используются.

`pet_hotel.read`: просмотр; `pet_hotel.operate`: брони и проживание;
`pet_hotel.manage`: боксы и условия. Миграция даёт директору все три права,
администратору — просмотр и работу с бронями. Грумеру права автоматически не даются.

Отключение сохраняет историю и действующие обязательства. Новые брони, переносы
и заезды блокируются; выезд, отмена и отметка незаезда остаются доступны по правам.
В ограниченном режиме открыть модуль можно из карточки дополнения или по сохранённой
ссылке. Отключение зоогостиницы не меняет состояние груминга и Авито.

Конкурирующие записи и переключатель дополнения используют один PostgreSQL
advisory lock. Ключ операции защищает создание и смену статуса от повторного
сохранения, включая восстановление уже выполненного запроса после отключения модуля; версии защищают от перезаписи более свежих данных. Изменения пишутся
в аудит. Общий SSE передаёт события `pet-hotel`, фронтенд обновляет запросы модуля
без полной перезагрузки; дополнительно список проверяется каждые 30 секунд.

Сайт зоогостиницы пока принимает обращение. Публичное бронирование, кабинет
зоогостиницы и MAX этим модулем не включаются. Текущий webhook MAX не менялся.

## Проверка и локальный стенд

Исходники: отдельная ветка `codex/pet-hotel-module-20261020`, база —
`663758ef8084ebf95f8fbe03d08dce87891dfdef`.
Принятый стенд груминга 4261–4264 и его сборка не изменялись.
Новые изолированные синтетические БД на 127.0.0.1:55440:
`pet_hotel_tests_20261020_qa` и `pet_hotel_preview_20261020_qa`.
Тестовая очистка допускается только в первой БД; preview сохраняет ручные проверки.
Сначала к синтетической базовой схеме применена миграция
`20261020130000_pet_hotel_module`. Производственные миграции не запускались.

```sh
npm run db:generate
npm run api:build
node --test tests/pet-hotel.integration.test.mjs
VITE_API_BASE_URL=/api npm run web:build
node scripts/pet-hotel-local-preview.mjs
```

В другом терминале, из этого же checkout:

```sh
VITE_API_BASE_URL=/api VITE_DEV_API_PROXY_TARGET=http://127.0.0.1:4292 npm --workspace @clinic-crm/web run dev -- --host 127.0.0.1 --port 4291
```

Адрес: `http://127.0.0.1:4291/pet-hotel`. Тестовые учётные записи находятся в
локальном `output/pet-hotel-module-20261020/preview-access.json` (0600).
QA API не читает `.env`, очищает окружение, разрешает только свои имена БД,
отключает внешние запросы, синхронизацию и отправки. Используются настоящие
контроллеры, guards, аудит и БД; брони, владельцы и питомцы вымышленные.

Тесты проверяют 8+4, сохранение исправленных названий, округление, копейки,
гонку двух броней, повтор запроса, принадлежность питомца, вид/вес/часы/минимум,
сохранение ставок, версии, заезд/выезд, просрочку, отключение и лицензию,
реальные HTTP-права и SSE. Счётчики клинических и груминг-записей и состояния
других дополнений не изменяются.

## Подготовка будущего выпуска и откат

Деплой пока не разрешён. Перед выпуском потребуются отдельная резервная копия БД,
проверка восстановления, применение новой миграции и согласованное включение
дополнения директором. Структура добавляется без удаления существующих таблиц.
Для оперативного отключения достаточно переключателя: сведения и действующие
брони сохраняются. При возврате старого приложения новые таблицы сохранять;
не удалять схему и не откатывать данные клиники ради выключения интерфейса.
