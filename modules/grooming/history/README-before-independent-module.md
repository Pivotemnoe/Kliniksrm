# Груминг: первая версия и подключение к CRM

Подготовлено в этом чате 19 октября 2026 года. Пользователь выбрал третий
фотографический макет из новой серии. AI-примерка клиента не включена.

## Реализовано

- Витрина: 38 пород собак и 8 разделов для кошек, по 3 иллюстративных
  референса (138 всего), фильтры вида питомца и размера собаки, сравнение,
  сохранение избранного и заметки на устройстве.
- Переходы кадров процесса, появления текста и лёгкие сдвиги фотографий при
  прокрутке. Движение можно отключить; системное уменьшение движения учтено.
- Сценарный помощник выбора и записи с кнопками; свободный AI-диалог не включён.
- Заявка переносит выбранные образы и пожелания. Время — желаемое, не свободный слот.
- Собственный Nest-модуль `GroomingModule` в публичном шлюзе.
- Отдельные таблицы `GroomingRequest`, `GroomingMaxDelivery`.
- Нормализация телефона, проверка согласия, каталога, источника, ограничение запросов.
- Один clientRequestId создаёт одну заявку. Изменённое содержимое с тем же ID — 409.
- У каждого адресата MAX своя доставка. SENT выставляется только после provider mid.
  Для 429 есть ограниченные отложенные повторы. Тайм-аут/неопределённый ответ —
  UNCERTAIN без автоматического повтора; требуется сверка сотрудником.
- Защищённый контракт импорта в CRM. Публичная витрина не обращается в базу клиники.

## Обязательное дополнение пользователя: самостоятельная бронь

Клиент должен выбирать конкретного грумера и реальное свободное время,
бронировать самостоятельно, получать кабинет на основе клиентского кабинета
клиники и подтверждения/напоминания в MAX. Это обязательный этап установки
CRM-модуля. Текущий код формы остаётся заявкой с желаемым временем.
Полное требование, проверенные пути переиспользования кода и критерии приёмки:
[SELF_BOOKING_REQUIREMENTS.md](SELF_BOOKING_REQUIREMENTS.md).

## Отдельное платное дополнение CRM

По дополнению пользователя груминг подключается отдельно для каждой клиники,
по умолчанию отключён и имеет собственное лицензионное право GROOMING.
После подключения появляется пункт «Груминг» слева и собственные вкладки:
календарь, записи, клиенты и питомцы, специалисты и графики, услуги,
уведомления, настройки. Карточка записи открывается отдельной панелью со своим адресом.
Общие сотрудники, клиенты, питомцы, вход кабинета и транспорт MAX переиспользуются.
Цена и платёжная интеграция пока не определены.

В текущем коде ClinicModuleInstallation и проверка лицензии уже есть для Авито;
реестр, права и обработку отключения ещё нужно обобщить для дополнений.
Проверенные точки подключения, вкладки, роли и сохранение будущих записей при
отключении описаны в [MODULE_REQUIREMENTS.md](MODULE_REQUIREMENTS.md).
Это обязательное требование следующего этапа, а не установленная функция.

## Что подключать в основном чате CRM

Манифест находится рядом: `manifest.json`. Не переносить груминг в клинические
Appointment, Visit или госпитализацию. Добавить в реестр ClinicModulesService
отдельный ключ GROOMING; настройка включения не удаляет сохранённые заявки.
Права: grooming.read — просмотр, grooming.operate — обработка своих заявок,
grooming.manage — настройки директора. Кабинет грумера — следующий этап.

Обмен выполняет сама CRM исходящими запросами к шлюзу:

1. GET /internal/v1/grooming/requests с X-Owner-Gateway-Secret.
2. В локальной БД создать заявку груминга с уникальным externalRequestId = id шлюза.
   В транзакции сохранить контакт, питомца, услугу, желаемую дату, notes, looks,
   consentVersion, статус NEW. Повтор импорта возвращает существующую запись.
3. Только после сохранения отправить POST /internal/v1/grooming/requests/:id/imported
   с JSON `{ "crmRequestId": "локальный ID" }`.
4. После обрыва между 2 и 3 повторить подтверждение; дубль записи недопустим.
   Другой crmRequestId для уже подтверждённой заявки отклоняется.
5. В текущем сценарии заявки сотрудник вручную согласует время. Этот импорт
   не заменяет обязательную самостоятельную бронь из SELF_BOOKING_REQUIREMENTS.md
   и не создаёт медицинский приём.

Сейчас реестр, меню, права и рабочий кабинет в основной CRM не менялись.
Это подготовленный контракт подключения, а не установленный модуль CRM.

## Настройка настоящей отправки

Пустой шаблон: `deployment.env.example`. Все значения — только на сервере.
GROOMING_MAX_BOT_TOKEN может задавать отдельного бота. Если пусто, используется
MAX_BOT_TOKEN. GROOMING_MAX_RECIPIENT_IDS — явно выбранные MAX user_id
администратора/грумера, запустивших бота. Один номер телефона не задаёт адресата.

До выбора бота, получателей, документа обработки данных и проверки реальной доставки
GROOMING_BOOKING_ENABLED остаётся false. Включение первой версии сайта пользователем
не подменяет отсутствующие параметры реальной доставки.

Для витрины проксировать /v1/public/grooming на публичный шлюз по HTTPS.
GROOMING_SITE_ORIGINS содержит точный origin витрины. Секрет синхронизации
не отправляется в браузер. MAX не связан с API или базой клиники напрямую.

## Локальная проверка

Создан отдельный тестовый Postgres: crm-grooming-qa-20261019,
127.0.0.1:55440, grooming_gateway_qa. Клинические БД и контейнеры не изменялись.
API-фикстура `tests/helpers/grooming-qa-server.mjs` слушает только
127.0.0.1:4194, перехватывает MAX и не загружает корневой .env.
Витрина http://127.0.0.1:4187 проксирует только свой grooming API.

Сборка: npm --workspace @clinic-crm/owner-gateway run build.
Проверки: tests/grooming-intake.integration.test.mjs; передать
GROOMING_QA_DATABASE_URL отдельной тестовой базы.
Квитанции синтетических сообщений: outputs/grooming-v1-20261019/max-test-receipts.jsonl.
Не использовать тестовые идентификаторы, документы или QA-флаги в production.

Референсы каталога и главный адаптированный кадр созданы встроенным ImageGen.
Исходные фотографии процесса: Goochie Poochie Grooming / Pexels.
Каталог не является портфолио салона; изображения не обещают результат стрижки.
Промпты и происхождение: design/provenance/v1 в проекте витрины.

## Результат проверки 19 октября

Сборки шлюза и витрины прошли. Проверки grooming intake — 4/4,
Sites worker — 4/4. В браузере проверены компьютер, планшет и телефон,
поиск, сравнение, сохранение, ошибки формы и сохранённая заявка с датой.
Повторные и одновременные подтверждения импорта защищены от смены CRM ID.
Подробная визуальная проверка: `prototypes/temichevvet-grooming-fitting-20261015/design-qa.md`.

PWA, Web Push, кабинеты и AI-примерка клиентской фотографии — следующие этапы.
Реальная доставка MAX и установка модуля в основной CRM ещё не подтверждены.
